# Тестирование

Запуск: `npm test` (однократно) или `npm run test:watch`. Движок Vitest, окружение по умолчанию — node; UI-тесты помечены `// @vitest-environment jsdom`.

## Слои тестов

### 1. Инварианты базы знаний — `src/domain/__tests__/kb.test.ts` (11 тестов)

Защита от «сломанного контента» при редактировании KB:

- ссылочная целостность: ассоциации, взаимодействия, red flags, гейты, rule-outs ссылаются только на существующие состояния и находки;
- веса 1–5, валидные направления и возрастные множители;
- у каждого состояния ≥2 поддерживающих правила, корректное окно возраста, описание без пустот;
- уникальность ID во всех коллекциях;
- ровно 4 уровня триажа в фиксированном порядке;
- возрастные группы покрывают 0–180 без дыр и пересечений;
- температурные пороги существуют и помечены `needs-veterinary-review`;
- зоонозные состояния содержат гигиеническую формулировку;
- red flags: ≥10 правил, непустые сообщения, консервативные формулировки.

### 2. Golden-кейсы движка — `src/domain/__tests__/engine.test.ts` (15 тестов)

- возраст вне 0–180 → безопасный fallback;
- гейтинг по возрастному окну (ЭТЭК есть в 5 дней, нет в 14);
- возрастные множители меняют вес (кейс с водянистой диареей в 14 и 27 дней);
- golden-кейс «водянистый скурс второй недели» → криптоспоридиоз probable, ротавирус probable, синдром обезвоживания possible, уровень urgent от гейта;
- соответствие полос и порогов `BAND_THRESHOLDS`, лимит топ-5;
- red flags: лежачее состояние → emergency; кровавая диарея+лихорадка+вялость → emergency и сальмонеллез probable; лихорадка 41,2 → emergency (стекинг порогов);
- нормотермия → никаких флагов, monitor;
- гейты: умеренное обезвоживание → urgent без red flags;
- «здоровый» кейс с явными отрицаниями → monitor, пустой топ;
- консервативный дефолт «положительные находки → минимум планово»;
- missing info: неотвеченный ключевой вопрос попадает в «Уточнить для оценки»;
- rule-out заметки показываются контекстно и не скорятся;
- детерминизм: два запуска → идентичный результат.

### 3. Сводка — `src/domain/__tests__/summary.test.ts` (6 тестов)

Шаблонная генерация: заголовок/возраст/анамнез, уровень срочности с причинами, направления «НЕ ДИАГНОЗ» с полосами, зооноз-предупреждение, недостающие данные, дисклеймер; отсутствие утечек (`undefined`, `::no`, `[object`); устойчивость к пустому кейсу.

### 4. Конфигурация PWA/деплоя — `src/pwa/__tests__/config.test.ts` (8 тестов)

- манифест: standalone, тема, start_url/scope, иконки 192/512 + maskable, lang=ru;
- `resolveBase()`: project pages → `/<repo>/`, user site → `/`, `VITE_BASE` оверрайд;
- deploy-workflow: npm ci → test → build, официальные Pages actions, минимальные permissions.

### 5. UI smoke — `src/ui/__tests__/ui.test.tsx` (4 теста, jsdom)

Онбординг на первом запуске; переход к шагу возраста после подтверждения; валидация возраста (300 дней → ошибка); восстановление состояния после перезагрузки с принятым дисклеймером.

## Что тестировать при изменениях

| Изменение | Обязательные тесты |
|---|---|
| Правка KB | все — особенно kb.test (инварианты) и engine.test (golden) |
| Правка engine | engine.test + summary.test (контракт вывода) |
| Новый red flag/gate | kb.test + добавить golden-кейс в engine.test |
| Новый экран UI | ui.test.tsx smoke |
| Изменение деплоя | config.test.ts |

## Добавить golden-кейс

В `engine.test.ts`: соберите кейс через `buildCase(ageDays, {...})` (answers — `yes()`/`choice()`/`number()`), прогоните `assess(kb, case)`, зафиксируйте ожидания по уровню срочности, составу и полосам кандидатов. Предпочтительны клинически осмысленные кейсы — они же документация поведения движка.
