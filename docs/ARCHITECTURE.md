# Архитектура

## 1. Слои

```
┌──────────────────────────────────────────────┐
│ UI (React + Tailwind)  src/ui/*               │  тонкий слой: рендер + ввод
├──────────────────────────────────────────────┤
│ Состояние приложения   src/state/*            │  wizard-форма, localStorage
├──────────────────────────────────────────────┤
│ Домен (чистый TS)      src/domain/*           │  БЕЗ React/DOM/Date/random
│  ├ engine.ts      — триаж-движок (pure)       │
│  ├ findings.ts    — выводы и словарь находок  │
│  ├ summary.ts     — шаблонный NLG сводки      │
│  ├ types.ts       — типы домена               │
│  └ kb/*           — БАЗА ЗНАНИЙ (данные)      │
└──────────────────────────────────────────────┘
```

Правило зависимостей: UI → состояние → домен. Домен ничего не импортирует из UI.

## 2. Модель данных движка

**Единая валюта движка — булевы находки (findings).** Ответы маппируются:

| Ввод | Находки |
|---|---|
| boolean «да» | `<id>` |
| boolean «нет» | `<id>::no` (явное отрицание) |
| choice-опция | option.findings[] |
| число | все подходящие диапазоны (пороги стекаются: 41,0 °C дает и fever, и high-fever) |
| не отвечено | никаких находок — движок никогда не предполагает |

## 3. Конвейер `assess(kb, input) → Assessment`

1. **Валидация возраста** → band (`d0-7 … d91-180`) или безопасный fallback.
2. **Red flags** (13 правил: allOf + anyOf + возрастные фильтры) → уровень `emergency`, сообщения в баннер.
3. **Severity gates** (12 правил) → «пол» срочности (urgent/prompt) независимо от диагноза.
4. **Скоринг кандидатов**: для каждого состояния в возрастном окне:
   `score = prior + Σ(веса «за» × возрастной множитель) − Σ(веса «против») + бонусы взаимодействий`.
5. **Бондинг** по фиксированным порогам: `≥13 probable, ≥8 possible, ≥4 low`, ниже — скрыт. Топ-5.
6. **Missing info**: поддерживающие находки с весом ≥3 из неотвеченных вопросов.
7. **Консервативный дефолт**: есть положительные клинические находки и уровень monitor ⇒ минимум `prompt`.
8. **Rule-outs**: контекстные несскоринговые заметки.

Ключевое решение безопасности: **срочность и диагноз — независимые модули**. Баллы не могут сделать результат «экстренным», но red flags всегда могут.

## 4. База знаний

`src/domain/kb/*` — типизированные данные (TS-модули, проверка типов на компиляции):

| Файл | Содержимое |
|---|---|
| age-bands.ts | 5 возрастных групп 0–180 дней |
| symptoms.ts | 39 симптомов (boolean/choice/number + диапазоны) |
| history-factors.ts | 11 факторов анамнеза |
| conditions.ts | 18 состояний с окнами, уверенностью, зоонозами |
| rules.ts | ~180 ассоциаций + 7 взаимодействий |
| triage.ts | 13 red flags, 12 гейтов, 4 уровня триажа, 4 rule-out |
| index.ts | сборка `kb`, версия и дата редакции |

Инварианты БЗ проверяются тестами (см. docs/TESTING.md): ссылки только на существующие находки/состояния, ≥2 поддерживающих правила на состояние, уникальность ID, валидность окон и весов, покрытие 0–180 без дыр.

Версионирование: `KB_VERSION` (semver) + `KB_DATE` + `reviewStatus` на уровне БЗ и статусы на каждом состоянии. Обновление контента = правка данных + bump версии (см. docs/KNOWLEDGE_BASE_GUIDE.md).

## 5. Состояние приложения

- `WizardData` (src/state/wizard.ts): форма опросника; «не отвечено» остается undefined.
- `storage.ts`: localStorage `ct.settings.v1` (дисклеймер, opt-in история) и `ct.history.v1` (последние 10 оценок). Все операции в try/catch — приложение работает и без storage.

## 6. PWA

- **vite-plugin-pwa, generateSW**: precache всего app shell + иконок (глоб `**/*.{js,css,html,svg,png,woff2}`, лимит файла 3 МБ). База знаний компилируется в бандл → офлайн целиком.
- `navigateFallback: <base>index.html` — SPA-навигация офлайн и онлайн.
- `registerType: 'autoUpdate'` + `registerSW({ immediate: true })` — обновление при следующем визите.
- **base path**: `resolveBase()` (src/pwa/basePath.ts) — в CI `GITHUB_REPOSITORY=owner/repo` → base `/repo/`; `owner.github.io` или локально → `/`; ручной оверрайд `VITE_BASE`. Покрыто тестами.
- **404.html** генерируется плагином в vite.config с захардкоженным base — redirect со «старых» глубоких ссылок до активации SW.
- Манифест: `src/pwa/webmanifest.ts` (типизирован и покрыт тестами), standalone, тема #166534, иконки 192/512 + maskable.
- Иконки генерируются скриптом `scripts/generate-icons.mjs` (чистый Node, PNG-энкодер на zlib, 2× supersampling).

## 7. Сборка и деплой

- `npm run build` = `tsc --noEmit && vite build` (strict-типы до сборки).
- GitHub Actions: `.github/workflows/deploy.yml` — npm ci → `npm test` → build → `upload-pages-artifact` → `deploy-pages`. Права: `contents: read, pages: write, id-token: write`.

## 8. i18n

Весь UI-текст — в словаре `src/i18n/strings.ts` с типом `Strings = typeof strings`: пропущенный ключ = ошибка компиляции. Клинические тексты живут в KB (рядом с данными). Добавление языка = второй словарь той же формы + переключатель в настройках (запланировано на v1.1).

## 9. Осознанные упрощения MVP

- Без роутера: state-machine экранов (5 экранов) — меньше точек отказа на Pages.
- Без IndexedDB: истории из 10 записей достаточно localStorage.
- Без рантайм-валидации KB: инварианты ловят тесты на CI.
- Сводка — текст (+ печать), PDF отложено.
